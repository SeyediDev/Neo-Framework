# مهلت دریافت اطلاعات — ۲۴ اکتبر ۲۰۲۶

## مسئله و اصلاح

در صفحهٔ اصلی و Workspace، فراخوانی `abort()` به‌تنهایی پایان انتظار را تضمین
نمی‌کرد. اگر fetch یا خواندن بدنه به لغو واکنش نشان نمی‌داد، کنترل‌ها معطل
می‌ماندند. در Workspace، انتظار برای `reader.cancel()` نیز همین مشکل را داشت.

اکنون درخواست و هر مرحلهٔ خواندن پاسخ با سیگنال لغو رقابت می‌کنند. سقف کل همان
۵۰ ثانیه است؛ تعویض سازمان نیز انتظار قبلی را تمام می‌کند. پاسخ یا خطای دیررس
مشاهده می‌شود ولی اجازهٔ نمایش داده یا آزادکردن کنترل‌های درخواست جدید ندارد.
پاک‌سازی stream بدون انتظار انجام می‌شود و شکست آن مانع تلاش مجدد نمی‌شود.
سقف ۴MiB بدنهٔ Snapshot، رفتار no-store و اعتبارسنجی داده حفظ شده‌اند.

fixture حالت connected در آزمون قدیمی مرورگر، سابقه را صریحاً NotConnected
اعلام می‌کند؛ اتصال کاتالوگ به معنای آماده‌بودن سابقه نیست.

## اعتبارسنجی

چهار مجموعهٔ JavaScript محصول با Node و `--test-isolation=none` اجرا شدند:
portal-client، service-catalog، workspace-ui و workspace-transport.
۹ حالت جدید نسبت به مبنا، دریافت/بدنهٔ بی‌پاسخ، پاسخ و خطای دیررس، تعویض سازمان،
stream بیش‌ازحد بزرگ و خطای پاک‌سازی را می‌سنجند. چهار regression اولیه پیش از
اصلاح با timeout شکست خوردند. اجرای نهایی **۶۹ آزمون موفق** داشت: صفحهٔ اصلی
۲۱، کاتالوگ ۷، فضای کار ۲۹ و transport برابر ۱۲؛ شکست یا skip وجود نداشت.

این آزمون‌ها بدون شبکه و با پاسخ‌های مصنوعی‌اند؛ پذیرش دیداری یا موفقیت
reader مرکزی، دادهٔ سازمان، SSO یا مالی را اثبات نمی‌کنند. اصلاح runtime فقط
JavaScript است؛ تنظیمات، قراردادهای مرکزی و احراز هویت تغییر نکرده‌اند.
مهارت‌ها و MCP قرارداد متأثری ندارند؛ README رفتار زمان انتظار را توضیح می‌دهد.

## وضعیت وابستگی‌ها

تشخیص قبلی HTTP503 readerهای کاتالوگ و آماده‌نبودن DiscoveryPath با این تغییر
حل‌شده محسوب نمی‌شود. تحویل اتصال مالی در چت مالک جداگانه در حال نهایی‌شدن است؛
این اصلاح شامل ادغام یا فعال‌سازی آن نیست. هیچ داده، عضویت یا دسترسی ساخته نشد.

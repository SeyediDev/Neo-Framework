# بازگشت به فضای کار پس از ورود — ۲۶ اکتبر ۲۰۲۶

پیش‌تر مسیر `/login` پس از ورود موفق همیشه کاربر را به `/` می‌فرستاد؛ ورود
دوباره از گزارش مصرف یا خدمات سازمان، صفحه، تب و سازمان قبلی را از دست می‌داد.
اکنون لینک ورود، مقصد محدودِ همان صفحه، تب و سازمان تأییدشده را نگه می‌دارد.
مثلاً ورود از تب مصرف سپهر به `/Workspace?tenantId=…#usage` برمی‌گردد.
شناسهٔ سازمان فقط راهنمای ناوبری است؛ مقصد عضویت و اختیار را دوباره بررسی می‌کند.

## قرارداد اجرا

- `PortalSignIn` فقط `/`، alias آن `/Index` و `/Workspace` را می‌پذیرد و مسیر
  کانونی می‌سازد. تنها query قابل انتقال `tenantId` با Guid غیرصفر و تک‌مقداری
  است؛ handlerها، queryهای دیگر و return URL تو‌در‌تو منتقل نمی‌شوند.
- hash صفحهٔ اصلی فقط `top`، `workspace` و `centers` است؛ Workspace فقط
  `catalog`، `requests`، `services`، `usage`، `publish` و `review` را می‌پذیرد.
  نمایش تب، مجوز اجرای عملیات یا نقش ایجاد نمی‌کند.
- URL بیرونی، مسیر شبکه‌ای، backslash، نویسهٔ کنترلی، مسیر ناشناخته و ورودی
  بلندتر از ۲۰۴۸ نویسه به `/` برمی‌گردند. پارامتر returnUrl تکراری نیز رد می‌شود.
- مقصد پاک‌سازی‌شده در AuthenticationProperties و state محافظت‌شدهٔ OIDC
  قرار می‌گیرد. callback ثابت `/signin-oidc`، Code + PKCE و ورود مستقیم
  Keycloak تغییر نکرده‌اند. token به URL، HTML، storage یا log اضافه نمی‌شود.
- HTML اولیه مقصد را از مدل تأییدشده می‌سازد. ناوبری مرورگر لینک ورود را پس
  از تغییر سازمان و تب به‌روز می‌کند؛ هنگام انتظار یا خطا سازمان قبلی پاک است.
  تغییر تب با replaceState رویداد hashchange نمی‌سازد، پس Workspace هم‌زمان
  مقصد ورود را صریح به‌روز می‌کند. خواندن fragment به تب‌های مجاز محدود است.

## وابستگی مرکزی

probe تازه با credential و scope موجود `platform.catalog`، صدور توکن 200
و هر دو reader سازمان/کاتالوگ را 503 مشاهده کرد. DiscoveryPath همچنان خالی
است. خروجی بدون credential یا token در
`.artifacts/portal-sso-return-20261026/central-probe.log` نگه داشته شد.
[تشخیص پیشین مالک مرکزی](../../../docs/fanasa-platform-control-center/workstreams/portal-reader-503-diagnosis-2026-10-23.md)
نبود تنظیمات reader و ثبت محلی client را مشخص کرده است؛ این probe تازه صرفاً
وضعیت HTTP را تکرار کرد و تغییری در تنظیمات یا دادهٔ مرکزی نداد.

این اصلاح درخواست یا خرید واقعی، grant، scope، نشست مالی یا API مرکزی را فعال
نمی‌کند. Skill اتصال SSO از قبل بازگشت local/allow-listed را الزام کرده است؛
قرارداد Skill و MCP تغییر نکرد و README محصول با رفتار جدید هماهنگ شد.

## آزمون‌ها

پنج مجموعهٔ JavaScript با **۱۰۱ آزمون** موفق‌اند: portal-client=27،
service-catalog=11، workspace-ui=37، workspace-transport=12 و consumer-billing=14.
سه آزمون تازه، ساخت مقصد محدود، تغییر hash صفحهٔ اصلی و تغییر تب Workspace
با replaceState، تغییر سازمان پذیرفته‌شده و پاک‌شدن زمینه در خطا را بررسی کردند.

بیلد Release وب، Razor و Portal.Tests با صفر خطا و صفر هشدار موفق شد.
**۱۶۵ بررسی .NET** شامل ۴۰ بررسی تازهٔ مقصد و challenge واقعی middleware
OIDC با metadata و credential کاملاً مصنوعی موفق‌اند. در چهار درخواست مستقل،
state تولیدشده توسط middleware باز و RedirectUri آن بررسی شد؛ مقصد مجاز،
URL بیرونی، returnUrl تکراری و نبود پارامتر پوشش داده شدند. callback ثابت،
Authorization Code و S256 نیز بررسی شدند. هیچ درخواست شبکه یا token واقعی
در این آزمون‌ها وجود نداشت. ساخت از بسته‌های از قبل restoreشده بود؛ ممیزی
آنلاین تازه انجام نشد.

اجرای نخست آزمون OIDC در fixture از root provider مشترک به‌جای scope مستقل
هر درخواست استفاده کرد و بعد از اولین challenge شکست خورد. fixture اصلاح
و مجموعه کامل دوباره موفق شد؛ لاگ شکست و اجرای نهایی جداگانه در artifact
محفوظ‌اند. اجرای مجدد همان آزمون‌ها، شمارش اضافه محسوب نمی‌شود.

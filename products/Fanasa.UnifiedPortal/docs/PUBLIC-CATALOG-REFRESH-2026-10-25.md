# تکمیل تازه‌سازی کاتالوگ عمومی — ۲۵ اکتبر ۲۰۲۶

## محدوده و رفتار

مالک این اصلاح چت «پنجره واحد» است. مبنای شروع `21d5aea` در develop بود؛ چت
مرکز راهبری روی تحویل ناشر و اسناد حسابداری کار می‌کرد. فایل‌های runtime این
اصلاح فقط `service-catalog.js` هستند. فایل‌های مالی، Program، کاتالوگ مرکزی،
SSO و تنظیمات محیط تغییر نکردند.

در صفحهٔ عمومی، دریافت کاتالوگ بدون نشست ورود مسیر مستقلی دارد. پیش از اصلاح،
تنها abort پس از ۵۰ ثانیه اجرا می‌شد؛ fetch یا بدنهٔ پاسخ نامتعاون می‌توانست
دکمهٔ تازه‌سازی را برای همیشه معطل نگه دارد. اکنون انتظار درخواست و بدنه با
همان سیگنال پایان می‌یابد. پاسخ و خطای دیررس مشاهده می‌شوند ولی به renderer
نمی‌رسند. درخواست تازه پس از timeout مجاز است و کلیک‌های همزمان، درخواست
تکراری ایجاد نمی‌کنند.

دکمهٔ تازه‌سازی کاتالوگ و `aria-busy` پیام وضعیت، چرخهٔ invalidate/render/failed
را دنبال می‌کنند. این رفتار برای تازه‌سازی احرازشده نیز همان درخواست موجود فضای
کار را استفاده می‌کند؛ query تازهٔ grant اضافه نشد. معرفی خدمت و لینک درخواست
رسمی باقی‌اند؛ لینک ورود قبلی هنگام invalidate حذف می‌شود. timeout پیام روشن
و امکان تلاش مجدد دارد و به فهرست خالی موفق تبدیل نمی‌شود.

## شواهد محلی

چهار تست تازه به مجموعهٔ موجود کاتالوگ اضافه شدند. اجرای پیش از اصلاح، دو
timeout و یک شکست وضعیت دکمه را تأیید کرد؛ کنترل جلوگیری از درخواست تکراری از
ابتدا موفق بود. سپس پنج مجموعهٔ JavaScript موجود اجرا شدند:

| مجموعه | تست موفق |
|---|---:|
| portal-client | ۲۱ |
| service-catalog | ۱۱ |
| workspace-ui | ۳۱ |
| workspace-transport | ۱۲ |
| consumer-billing | ۱۴ |

مجموع **۸۹ تست** با صفر شکست، skip و لغو موفق شد. همهٔ درخواست‌ها مصنوعی‌اند؛
این اجرا شاهد دیداری، SSO یا دسترسی واقعی به داده نیست. C# و قراردادهای مالی
تغییر نکردند؛ مجموعه‌های دات‌نتِ قبلاً پذیرفته‌شده بی‌دلیل تکرار نشدند. ساخت
بستهٔ محلی و نتیجهٔ آن پس از آماده‌شدن جدا ثبت می‌شود.

README و جدول وضعیت فضای کار نیز اصلاح شدند تا reader مالیِ پیاده‌شده و
غیرفعال، «پیاده نشده» معرفی نشود. UI workflow ساده‌تر شده اما API/Schema یا
قرارداد Skill/MCP تغییر نکرده است؛ بازنویسی آن‌ها لازم نیست.

## باقی‌ماندهٔ اتصال واقعی

فعال‌سازی کاتالوگ و گزارش مالی زنده، چرخهٔ واقعی درخواست/عرضه، پذیرش خرید و
اجرای CI معتبر وابستگی‌های مستقل‌اند. این اصلاح آن‌ها را انجام‌شده اعلام
نمی‌کند. مقدارهای اتصال مالی خالی و feature خاموش ماند؛ هیچ user، grant،
scope، تنظیم Gateway یا انتشار VPS در این اصلاح تغییر نکرد.

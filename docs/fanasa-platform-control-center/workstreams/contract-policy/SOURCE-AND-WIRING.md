## Current decision semantics

`AccessPolicyStore.Evaluate(tenant, subject, permission, now)` reads active tenant policy state first ([AccessPolicies.cs:21](/E:/SJVS/Projects/Neo/products/Fanasa.AccessManagement/src/Fanasa.AccessManagement.Web/AccessPolicies.cs:21)). An inactive or unknown tenant causes lookup failure rather than one of the four Decision values. For an existing active tenant:

1. An unsupported fixed permission returns `NotApplicable`; an inactive/missing membership returns `Deny` (lines 63–64).
2. Published patterns for the permission match half-open absolute and UTC daily windows (lines 67–74). Role/unit matching uses active appointments, positions and units (lines 76–82).
3. An explicit matching Deny wins (lines 86–87). Missing potential Deny references produce `Indeterminate`; missing Permit references do so only when no other valid Permit/manual grant exists (line 90).
4. A valid direct grant **OR** at least one matching Permit pattern yields `Permit` (lines 89–91). A policy-based Permit adds `audit`; a grant-only Permit has no obligation. Otherwise the result is `NotApplicable` (line 92).

The evaluator never reads entitlements, subscriptions, offer validity, purchased features, eligible product roles, resource tenant/product binding, allocation limits or zone. Thus `contract active AND membership active AND explicit assigned authority AND tenant/resource/action bound` is a target gap. A stale grant cannot be allowed to bypass a suspended projection in the new slice.

`Evaluate` is read-only in source. `Authorize` ([AccessPolicies.cs:94](/E:/SJVS/Projects/Neo/products/Fanasa.AccessManagement/src/Fanasa.AccessManagement.Web/AccessPolicies.cs:94)) wraps evaluation in a transaction, emits the `audit` outbox event and returns bool. It checks only the known name `audit`; it is not a generic unknown-obligation rejection mechanism. The new decision endpoint should use pure evaluation and return obligations for the PEP to fulfill. Audit, rate/quota admission and reservation remain separate effects.

The four decision assertions, end-exclusive window and missing-reference behavior are visible in [GovernanceTests.cs:68](/E:/SJVS/Projects/Neo/products/Fanasa.AccessManagement/tests/Organization.Tests/GovernanceTests.cs:68), lines 69–86 and 92. Their existence is not a live authorization acceptance result.

## Target integration seams, proposed only

Keep these interfaces within the existing PCC host/module boundary. Interface names here are proposed adapters, not registrations that already exist.

| Adapter | Input / output | Required boundary |
| --- | --- | --- |
| `IContractAccessInbox` | Authenticated producer identity plus versioned lifecycle envelope → received/duplicate/conflict/stale result. | Validate schema and producer scope before a local transaction. Key inbox by producer + event ID; use canonical payload comparison. Commit receipt and projection together, order by aggregate version, retain history and fail on ambiguous version conflicts. `occurredAt` and `effectiveAt` are not substitutes for sequence. |
| `IContractAccessProjector` | Validated business event and known product/offer/subscription references → `ContractAccessProjection`. | Translate approved parameters into feature eligibility, eligible roles, validity and typed limits only. | `IContractAccessProjectionReader` | Consumer tenant + product + trusted request time → current accepted projection/version and freshness. | Verify owner/consumer relationship through the offer/subscription reference. Keep owner tenant and consumer tenant independent for SaaS. Suspended/expired/terminated state and effective bounds must be checked online. Missing/stale references fail closed. |
| `IAccessAttributeSnapshotProvider` (PIP) | Validated principal/client, consumer tenant, registered resource/action and server environment → immutable trusted snapshot. | Join active tenant/membership, assigned role/direct authority, projection, policy revision, resource binding, zone and server time. Mark missing required attributes explicitly. Client-provided tenant, role, contract version or limits do not confer authority. Snapshot source versions/freshness must be auditable. |
| `IContractPolicyDecisionEvaluator` (PDP) | Versioned request plus trusted snapshot → versioned `Decision`. | Evaluate the required AND gate before policy combination; retain explicit Deny and missing-required-attribute Indeterminate. | `IAccessDecisionEnforcer` (PEP adapter) | Typed Decision plus operation context → execute/stop and enforcement evidence. | Execute only Permit after every mandatory obligation is recognized and fulfilled. Unknown obligation, timeout, stale version or failed admission stops execution. Gateway/backend retain independent token/resource/action checks. An HTTP 200 decision response must be parsed; it does not itself authorize forwarding. |

2. Integrate the inbox/projector beside existing Fabric tenancy, preserving transaction and version/history semantics. Attach policy publication/distribution as separately observable states rather than pretending receipt means enforcement.
3. Build a trusted PIP snapshot adapter over the current registry, tenancy, organizational assignment and accepted projection readers. Guard product/action/consumer binding and snapshot freshness.
4. Expose pure Decision evaluation through a dedicated interface/endpoint. The current governance simulation remains useful as simulation until integration acceptance.
5. Connect Gateway/backend PEP adapters to the Decision schema. Seat checks remain in tenancy/organization; TPS/burst/quota admission remains owned by Gateway/limiter, and budget/usage/ledger remain owned by Accounting.
6. Accept a real selected product/API using positive and negative grants, different owner/consumer tenants, suspend/revoke/freshness and direct-backend rejection. Offline fixture results cannot satisfy this gate.

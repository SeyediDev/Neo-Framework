# Transactional CRUD resources

These APIs are source-pinned, opt-in additions; older published packages may not contain them. Inspect the consuming version first. Use the repository's CrudResourceDemo or MCP example `crud-resource-demo` with the exact baseline from `neo_search_docs` when available.

- Define `CrudDefinition<TCreate,TUpdate,TRead,TEntity,TKey>` with explicit Create/Update/Read mapping. Put invariants in domain methods; omit server-owned fields from write DTOs. `Scope` restricts existing rows; creation must assign tenant/owner from trusted identity itself.
- Declare a policy for every enabled operation. Null explicitly permits anonymous access. HTTP controllers enforce these policies; direct service calls do not. The application may have additional MVC/fallback authorization.
- Register `AddNeoCrudResource<TContext,TDefinition,TCreate,TUpdate,TRead,TEntity,TKey>()`. Inject `ICrudService<TDefinition,TCreate,TUpdate,TRead,TKey>` to distinguish definitions sharing DTOs.
- The six-parameter `GenericCrudControllerBase<TCreate,TUpdate,TRead,TEntity,TKey,TDefinition>` requires a route on the concrete controller. List/filter/sort are bounded and allow-listed; Id breaks sorting ties. Disabled operations return 405. Validation/missing/conflict return 400/404/409.
- Entity implements `IConcurrencyVersion`; map `ConfigureNeoConcurrency()` and register `NeoConcurrencyInterceptor` after any domain-event interceptor. Existing databases need a Version migration/backfill. Raw SQL, ExecuteUpdate and external writers must implement version checking and advancement themselves.
- PUT accepts `{ data, expectedVersion }`; DELETE uses the expectedVersion query parameter. Both modes reject stale forms. Never silently reload the current token and resubmit a losing user's write. Return `stale_version` for client review.
- Optimistic is the default. Pessimistic requires SQL Server and holds UPDLOCK/HOLDLOCK inside one request transaction; no SQLite/Redis/memory substitute. LockWait is 1..30 seconds, rounded upward to a whole SQL command-timeout second. `resource_busy` means retry the complete operation after checking the current version. Multi-record invariants require a dedicated transaction and consistent lock order.
- Mutations own a fresh scoped DbContext and transaction; existing tracked state, ambient context transaction and automatic EF retries are unsupported. `ICrudTransactionParticipant<TContext,TEntity>` stages translations/Outbox in that same context before commit. External calls do not roll back. New deletion is hard delete; preserve domain-specific soft-delete requirements in a dedicated handler when needed.
- `CrudRuntimeDoctor.CheckAsync` resolves fresh scopes and checks EF metadata, registrations and policy names, with optional read-only connectivity. It does not verify physical schema or migrate. Resolving application constructors can execute their code. Keep reports local. MCP `neo_diagnose_project` stays static and does not execute this Doctor.

Verify the actual HTTP create Location, stale update/delete, denial without mutation, rollback of entity plus participant effects, and a provider-specific concurrency race. A build or SQLite test cannot establish SQL Server locking.

For an authorized new scaffold, the repository CLI exposes `neo new feature <Name> --namespace <App.Namespace> --route <items> --output <new-directory> --neo-root <matching-checkout>`. It reuses CrudResourceDemo source and emits a standalone application; it does not merge with an existing app, overwrite directories, run a build or create a database. Read the generated README and adapt authentication, scope, migrations and message dispatch before integrating. The output references the source checkout via NeoRoot, not an assumed NuGet release. The CLI can also run as `dotnet tools/Neo.Companion/src/Neo.Companion.Cli/bin/<configuration>/net10.0/Neo.Companion.Cli.dll` after building.
